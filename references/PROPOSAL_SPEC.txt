1　專案概述
本專案規劃一套供管理者使用的 AI Agent，以「決策前風險推演」為核心，保留人工對話與即時監測兩種模式，並支援工程變更影響分析。系統查詢獲授權的資料、使用可驗證工具、主動質疑假設，並比較決策後果；重要行動必須由管理者核准。
1.1　專案背景
構想源自我在業界兼任團隊專案經理及工程工作的經驗，面對的客戶包含國際半導體大廠。工作同時涉及技術問題、專案統籌、資源配置、交期與對內外溝通。許多研發案件沒有標準答案，必須在資訊不完整的情況下判斷後果；尤其對經驗尚在累積的管理者而言，容易忽略跨部門依賴、關鍵假設與潛在風險。
1.2　產品定位與驗證範圍
長期產品定位為跨領域管理決策輔助系統：依不同產業，利用使用者授權的企業資料、專業知識及專用分析工具建立判斷依據。本學期先以「軟硬體整合設備」的合成研發專案進行概念驗證（PoC）；單一領域的測試不代表已證明跨領域專業能力。
2　問題描述
核心問題　管理者做出研發決策前，如何在資料分散、結果不確定的情況下，提早看見技術限制、連鎖影響與替代方案？
• 資訊分散：需求、規格、測試、排程與會議紀錄難以同步確認。
• 決策盲點：方案可能忽略電氣、軟體、機構、成本及交期的相依關係。
• 風險發現過晚：工程變更與外部事件可能在執行後才被發現影響。
• 分析成本：重複蒐集資訊與初步評估高度占用主管、資深工程師及顧問時間。
• 資料安全：企業智慧財產與客戶資料不能任意傳送至外部 AI 服務。
與一般聊天問答的差異，是 Agent 能按目標主動取證、使用工具檢核、依結果追問及產生可追溯的建議；資料不足時不將猜測寫成事實。
3　目標族群
主要服務各產業的專案經理、研發主管與技術主管。使用者可設定品質、交期、成本等優先順序；安全、法規及客戶強制規格則屬不能以偏好犧牲的必要限制。

4.2　主動監測模式：資料變更後分析風險
當授權的零件交期、測試結果或專案狀態更新，Agent 以事件觸發或定期比對偵測變化，沿相同分析流程重新檢查。若風險達提醒條件，主動向管理者提出問題與建議；自動提示可在系統內顯示，通知他人或更動計畫仍須核准。
本學期驗證方式　課程版以合成資料更新模擬「事件 → 分析 → 提醒」；企業系統的持續同步與真實即時性仍屬後續部署工作。
5　專案目標與預期價值
O1 整合授權資訊；O2 用工具驗證必要條件；O3 主動質疑並推演連鎖風險；O4 比較方案與管理偏好；O5 由管理者核准行動並記錄實際結果。商業目標是減少前期搜尋與重複分析工時、降低對少數高成本專業人力的反覆依賴；實際節省仍須未來企業試點驗證。

8.3　分析與執行規則
• 使用者主導：Agent 能詢問、質疑及提出不同意見，不能逕自修改任務、通知第三人或跳過審核。
• 確定性檢核：LLM 處理語意及方案；計算、權限、依賴遍歷與執行前驗證由可測試程式負責。
• 資料安全：文件只作為資料，不接受其中試圖改寫指令的文字；模型只能看到該次被授權的內容。
• 失敗處理：缺規格時追問；資料來源衝突時標示版本；工具錯誤或權限拒絕時停止相關步驟並說明。
8.4　兩種模式共用同一個閉環
觸發（人員提問／授權事件） → 資料與權限檢查 → Agent 取證與工具檢核 → 風險推演／補問 → 方案建議 → 管理者審核 → 核准後執行 → 地端記錄。監測事件可主動產生待處理問題；不需要等待使用者先開啟聊天。

9.1　模型路由：地端優先＋有限雲端
地端預設　原始文件、RAG 索引、任務資料與分析紀錄留在企業控制環境；機密及未分類內容只能由已核准的地端模型處理，若無可用模型則停止相關分析。
雲端例外　非機密片段須經企業政策、來源權限、使用者授權及資料最小化檢查，才可送到核准雲端端點。外送行為需留紀錄，不因使用者詢問就自動外送。
9.2　事件來源、停止條件與人工審核
授權系統提供事件時可觸發分析；不支援事件通知的來源可使用定期差異掃描。課程版只展示模擬事件，不保證毫秒級即時性。重要資訊缺漏、版本衝突、越權、工具上限或沒有合格方案時，回報限制或等待補充；外部寫入及通知須管理者核准。

10.1　專業適應能力與模型選擇
長期採「通用決策流程＋動態取得領域資料＋必要專用工具」。對不熟悉的產業，先依授權文件建立背景，再使用專業工具驗證；沒有資料或驗證工具時必須揭露限制。課程版優先評估可本地部署的開放權重 LLM（如 Qwen3-8B），依實際設備測試中文規格理解與 Tool 呼叫，不預設效能。
10.2　部署要求
依課程規範，LLM server 以外的介面、Agent、檢索、工具及紀錄服務均由 Podman 容器執行；提供 Containerfile、固定版本、環境設定、README 與可重現測試。企業混合部署不表示任何敏感資料都可送雲端。

12.3　雙模式與商業價值的驗證界線
期末另用合成資料變更事件，檢查「偵測 → 重新分析 → 去重 → 介面提醒」，記錄延遲與誤報。短期只能衡量分析品質與處理時間，不能用模擬測試宣稱已節省薪資、顧問費或提升真實決策成功率。
